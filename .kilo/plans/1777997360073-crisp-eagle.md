## Priority 4: Replace In-Memory Rate Limiter
**Goal**: Persist rate limiting across server restarts, support multi-instance

### Current State
- `lib/rate-limit.ts` uses `Map<string, RateLimitEntry>` (in-memory)
- Volatile on restart, won't work with multiple server instances
- No TTL cleanup (only manual cleanup every 5 min)

### Options
**Option A**: Database-backed (Prisma)
- Create `RateLimit` model with `key`, `count`, `resetAt`
- Simple, works with existing DB, no new infra
- Slightly slower than Redis, but acceptable for most use cases

**Option B**: Upstash Redis (recommended for production)
- Fast, distributed, built for serverless
- Free tier available
- Requires Redis integration

**Recommended**: Option A (minimal infra change, aligns with current architecture)

### Tasks
4.1 Add `RateLimit` model to Prisma schema
```prisma
model RateLimit {
  key       String   @id
  count     Int
  resetAt   DateTime
  updatedAt DateTime @updatedAt
}
```

4.2 Create database functions in `lib/db/rate-limit.ts`
- `getRateLimit(key: string)`
- `incrementRateLimit(key: string, maxRequests: number, windowMs: number)`
- `cleanupStaleEntries()`

4.3 Update `lib/rate-limit.ts` to use DB instead of Map
- Keep same API: `rateLimit(key, maxRequests, windowMs)`
- Replace Map logic with Prisma queries

## Priority 6: Add Error Boundaries
**Goal**: Graceful error handling for client component failures

### Analysis
- Client components (`"use client"`) lack error boundaries
- Any uncaught error crashes the component tree

### Tasks
6.1 Create `components/error-boundary.tsx`
```tsx
"use client"
import { Component, ErrorInfo, ReactNode } from "react"

interface Props { children: ReactNode }
interface State { hasError: boolean; error?: Error }

export class ErrorBoundary extends Component<Props, State> {
  state: State = { hasError: false }
  
  static getDerivedStateFromError(error: Error): State {
    return { hasError: true, error }
  }
  
  componentDidCatch(error: Error, info: ErrorInfo) {
    console.error("Uncaught error:", error, info)
  }
  
  render() {
    if (this.state.hasError) {
      return (
        <div className="p-4 text-center">
          <h2>Something went wrong</h2>
          <button onClick={() => this.setState({ hasError: false })}>
            Try again
          </button>
        </div>
      )
    }
    return this.props.children
  }
}
```

6.2 Wrap client components in error boundaries
- `app/(auth)/sign-in/page.tsx`
- `app/create-event/[token]/page.tsx` (EventCreationForm)
- `components/dashboard/TokenGenerator.tsx`
- `components/events/QRCodeDisplay.tsx`
- Any other `"use client"` components

## Priority 7: Implement CSRF Protection
**Goal**: Prevent Cross-Site Request Forgery attacks

### Current State
- Server actions (`app/actions/*.ts`) have no CSRF tokens
- Forms are vulnerable to CSRF

### Options
**Option A**: Use `next-auth` CSRF (already configured via `@auth/prisma-adapter`)
- NextAuth provides CSRF token for its own routes only
- Does NOT protect custom server actions

**Option B**: Implement custom CSRF for server actions
- Generate cryptographically signed token per session
- Include token in all formsPOST requests
- Verify token on server

**Option C**: Use `csrf-csrf` or `next-csrf` package
- Third-party library
- Easier to implement

**Recommended**: Option C (`csrf-csrf`) for quick, secure implementation

### Tasks
7.1 Install `csrf-csrf`: `npm install csrf-csrf`
7.2 Create CSRF middleware in `lib/csrf.ts`
7.3 Wrap server actions with CSRF protection
7.4 Add hidden CSRF token field to all client-side forms
